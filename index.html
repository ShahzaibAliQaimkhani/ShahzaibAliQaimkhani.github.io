Selected work

Dataset bias in multi-source gait biomechanics

Machine Learning and Data Analytics Lab (MaD Lab), FAU Erlangen-Nürnberg

I trained classifiers to predict which of five public databases a gait recording came from. Not because that's a useful thing to know — because if a model can recover the source from the signal, then any model trained on pooled gait data may be learning database artifacts rather than biomechanics. The classifier is a diagnostic instrument, not the goal.

What the data looked like

Inputs were gait cycles time-normalised to 101 points, drawn from five databases with different collection protocols and processing conventions. I ran four modality cases against each other: marker trajectories with ground reaction forces, inverse kinematics alone, inverse dynamics alone, and inverse kinematics combined with inverse dynamics. Each case passed through five scaling workflows — pooling before scaling, scaling per database then pooling, scaling per trial, and two variants in between. One of those workflows uses known database identity to select the scaler, so it functions as a diagnostic upper bound rather than a deployable pipeline, and I report it as such.

Why the model got simpler, not more complex

I began with a 1D CNN, which is the natural choice for a 101-point waveform: it learns local shape, peaks and transitions without hand-designed features. It worked, and it produced the first evidence that database source was highly separable. But I moved to a single-hidden-layer MLP for the final experiments, for three reasons. It matched the reference methodology I was comparing against, which made the results interpretable next to prior work. It isolated the effect of scaling workflow and input modality instead of confounding them with architectural choices. And it gave a far cleaner mapping for layer-wise relevance attribution. The simpler model was the more useful instrument.

Evaluation

Hyperparameter search covered six hidden sizes, three learning rates and five batch sizes — 90 configurations per fold and workflow, 2,250 fits per case. Cross-validation was grouped by participant, so every cycle from one person stayed inside a single outer fold; without that, a model can recognise a walker rather than a database and the whole result collapses. Model selection was on validation loss.

Results

Macro F1 for database-source classification, averaged across workflows, with a balanced re-run at 169 cycles per database to test whether class imbalance was driving the outcome:

Macro F1 by modality case, primary run against balanced sensitivity check
Case Input Primary Balanced Δ
1Marker + GRF97.31%98.86%+1.54 pp
2Inverse kinematics96.95%97.79%+0.85 pp
3Inverse dynamics99.67%99.41%−0.26 pp
4IK + ID99.78%99.68%−0.10 pp

Every representation carries source-specific information. Inverse dynamics is the strongest signal, which most likely reflects differences in processing convention between labs rather than differences in how people walk. The balanced run matters because the databases contributed unequal numbers of cycles: cases 1 and 2 improve once that's corrected, meaning imbalance was hurting the weaker workflows, while cases 3 and 4 stay near ceiling, meaning the inverse-dynamics signal is not an artefact of class counts.

Two things I will not claim. Cases 3 and 4 are both close enough to ceiling that adding kinematics to dynamics cannot be called a meaningful improvement. And a per-trial scaling workflow still separates the databases, so source identity is not carried by absolute amplitude alone.

What the models were actually using

I applied layer-wise relevance propagation through Zennit, using the epsilon rule at ε = 1e-6 on correctly classified samples, with positive relevance normalised and averaged per database. In the marker-plus-force case, relevance splits between marker trajectories and ground reaction forces, with force channels carrying more weight individually simply because there are fewer of them. In the combined kinematics-and-dynamics case, the attribution shifts with the scaling workflow: pooled scaling pushes relevance toward kinematics, per-database and per-trial scaling push it toward dynamics. That shift is itself a finding — preprocessing changes what the model looks at, not just how well it scores.

LRP here explains a source-prediction decision. It is not evidence of clinical or biomechanical importance, and I don't present it as such.

The point of all of it

Models trained on pooled gait datasets may be learning which lab recorded the data unless source bias is explicitly controlled. That is a problem for anyone hoping their model generalises across datasets, and it is the direction I would like to keep working in.

Bachelor's thesis, NED University (IIEE), Karachi

An IoT gateway bridging programmable logic controllers and field sensors to a cloud backend, handling protocol translation between industrial fieldbus and internet protocols. Live operational data fed a dashboard for real-time visualisation, historical analytics and remote actuation. The aim was condition-based maintenance on equipment that can't be taken offline to be inspected — catch a developing fault from its signal rather than servicing on a fixed calendar.
